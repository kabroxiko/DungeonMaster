# Dungeon Master Prompt Catalog

This document describes prompt templates embedded in `gmai-server` from this directory. Edit files here; paths are relative to `go/internal/prompts/promptfiles/`.

## Directory layout

| Folder | Role |
|--------|------|
| `core/` | Always-on DM persona and global style (`system`, `style`). |
| `rules/` | Guards, language directives, memory wrapper, intent router, scene grounding. |
| `skills/` | Mode-specific skills (combat, investigation, decision, adventure seed, character gen). |
| `templates/dm/` | Mustache injections, response envelope, party/PC context, combat handoff. |
| `templates/campaign/` | Campaign core generator (merged file + stage templates). |

## Loading

- `promptmgr.LoadPrompt(name)` expects a path relative to this tree (e.g. `rules/language_spanish.txt`, `templates/dm/inject_initial.txt`).
- `loadCampaignGeneratorParts()` reads `templates/campaign/generator.txt`, splits on a single `---` line: **build context** (system, world-only JSON rules) and **user template** (Mustache with `{{sessionSummary}}`, `{{languageInstruction}}`). `/generate-campaign` and `/generate-campaign-core` use both slices (build + full user text as system priming, then rendered user text as the user message), matching the old two-file behavior.

## Flow notes

- System messages are consolidated via `consolidateSystemMessages(...)` before sending to the model to preserve guard precedence.
- Campaign core is generated by `/generate-campaign-core` using `templates/campaign/generator.txt`. The API persists `campaignSpec`.
- Background stages use `generateCampaignStage` with `templates/campaign/stage_*.txt`.
- For initial adventures, `renderInitialCampaignInject` (`go/internal/gamesession/dm.go`) renders `templates/dm/inject_initial.txt` from the stored `campaignSpec` and prepends it to the `/generate` system stack, so the opening is written from the campaign's concept, conflicts, factions, NPCs and key locations instead of being invented. The stored `openingSceneFrame.directive` is injected as a mandatory instruction, and any place name it took from the old key locations is rewritten to the map name that replaced them (`reconcileDirectiveNames`). Key location names are reconciled against the players' map at render time (`campaignspec.AlignKeyLocationsToWorld`), which also repairs campaigns generated before place-name alignment existed, and the map's place names are listed with their kinds as the only settlements the opening may name.
- **Vellaris worlds:** every game carries `campaignSpec.vellarisWorld`, and `renderVellarisWorldInject` prepends `rules/vellaris_world.txt` + the rendered `templates/dm/world_vellaris.txt` to the `/generate` system stack. There is no second, invented topology: the map service is the only source of geography, so no template asks the model for a region graph and no code path injects one. The same block also feeds `templates/campaign/stage_keyLocations.txt` through `{{#hasVellarisRegions}}` / `{{vellarisRegions}}` **and `{{#hasVellarisPlaces}}` / `{{vellarisPlaces}}`**, so key locations are chosen from the map's own named places and tagged with regions that already exist. `campaignspec.AlignKeyLocationsToWorld` then enforces that guarantee server-side: a name the map knows is kept with the map's spelling, an invented or repeated name takes the next unused map name, and a location with no map name left is dropped — the model contributes `type` and `significance`, not geography. Key locations are aligned against **settlements only** (`SettlementNames`), never regions or lakes. **Every** campaign stage (factions, majorNPCs, keyLocations, opening frame) also gets `rules/vellaris_world.txt` + `templates/campaign/world_context.txt` in its system stack (`campaignWorldSystemBlock`), and the campaign core's build context lists the map's named places (`{{vellarisPlaces}}`, top 24) with a rule that any settlement named must come from them and at least two must be used.
- **Kinds:** Vellaris names are what they are, and the prompts say so. `campaignspec.PlaceKind` maps a map-text type to the word used everywhere (`City` → `settlement`, `Region` → `region`, `Lake`/`River` → `lake`/`river`, `Mountain_range`/`Other_mountains` → `mountains`, `Title` → `map title`). Normalized regions carry `type: Region` and `kind: region`; normalized places carry `kind`, and **region labels and the map title are not listed as places** (regions already have ids). `rules/vellaris_world.txt` requires the DM to respect the kind — a region is a territory (“in the region of X”), only settlements have streets and markets. Stored campaign documents are decoded from MongoDB, where arrays are `primitive.A`; `campaignspec.neighborSliceAny` and `llm.SliceValues` accept any slice type so a stored world is never mistaken for an empty one.
- **Surroundings:** every named place also says what the ground around it is like, read from the map's Voronoi graph (`surroundings.terrain`, `nearbyTerrain`, `coastal`, `lake`, `river`, `mountains`, `island`), and every region reports the terrain most of its land is (`regions[].terrain`). `campaignspec.surroundingsText` renders the place part as the phrase after each place name in `world_vellaris.txt`, `campaign/world_context.txt`, `campaign/generator.txt`, `stage_keyLocations.txt`, `character/world_context.txt` and `inject_initial.txt`; region terrain renders beside the region name in the same blocks. `rules/vellaris_world.txt` and `rules/character_world.txt` forbid contradicting either: a desert place or region has no river, stream or woods and an inland place has no harbour, so narration uses wells, cisterns and caravan roads instead. Nothing is added when the world reports nothing, so an older stored world simply prints names and kinds as before — its terrain appears once its world is regenerated.
- **Campaign generation runs on the map.** `prepareCampaignWorld` (`go/internal/gamesession/campaign_world.go`) runs before the creative seed and before any campaign text: a game that already has `campaignSpec.vellarisWorld` reuses it, otherwise the map service is asked once (`POST /api/world`) with settings from the request's `worldSettings` or from `DM_VELLARIS_SETTINGS_FILE`, and the answer is stored before generation continues. The settings are stamped with the game's language (`resolveCampaignLanguage` → `withCampaignLanguage`), so Vellaris generates place and region names in the language the table plays in; `rules/vellaris_world.txt` and `rules/language_spanish.txt` both state that world names keep that spelling rather than being translated to English. The rendered map image (`POST /api/world/map`) is downloaded in parallel with the campaign stages and stored for the show/hide map control. That world block is rendered by `templates/campaign/world_context.txt` and reaches both the generator's system stack (`BuildCampaignCoreSystemMsgs`) and its build context (`{{#hasVellarisWorld}}` / `{{vellarisRegions}}` in `generator.txt`).
- `campaignSpec.vellarisWorld` and `campaignSpec.vellarisSettings` are DM-only: `RedactCampaignSpecForClient` removes them (they carry coordinates players must not see) and `HasSubstantiveCampaignSpec` ignores them, so storing a world early does not make an unfinished game look ready. Clients learn about the rendered map through `campaignSpec.mapImage`, which is a **map marker, not campaign content**: `campaignspec.mapMarkerKeys` keeps `mapImage` / `mapImageError` out of the readiness check (mirrored in `campaignSpecReady.js`), because character generation stores the map before any campaign exists and a game holding only a map must still be startable.
- **Characters are written on the same map.** `/generate-character` calls `campaignWorldForCharacter` (`character_world.go`) before it builds its prompt: a game that has no `campaignSpec.vellarisWorld` yet creates one, exactly as the campaign path does, and a game that has one reuses it. World creation is serialised per game id (`lockCampaignWorld`), so two players pressing generate at the same moment get **one** world — the second waits on the lock and then reads what the first stored — and no table ever ends up with a different map per player. The block that reaches the prompt is `rules/character_world.txt` + `templates/character/world_context.txt` (`characterWorldSystemBlock`, 12 places): the PC's homeland must be one of the listed regions or places and every place named in `brief_backstory` must be copied from that list.
- `campaignSpec.vellarisWorld` mirrors what the map service returns, so importing a world is a copy rather than a rewrite: `{seed, worldSize, imageWidth, imageHeight, mapImageUrl, regions[{id,name,terrain,centerX,centerY,centerCount}], places[{name,type,x,y,surroundings{terrain,nearbyTerrain,coastal,lake,river,mountains,island}}], routes[{from,to,distance,days,crossesWater,regionsCrossed,terrain[{terrain,share}]}]}`. `campaignspec.NormalizeVellarisWorld` formats every value for the prompt and caps it, so the templates never print float noise. `surroundings` is the map's own answer for the ground around a place (its terrain, the bordering terrain, and whether the coast, a lake, a river, mountains or an island are at hand); `surroundingsText`/`surroundingsSuffix` are the phrase the templates print, and a world that reported nothing gets no phrase rather than an invented terrain.
- `skills/adventure_seed.txt` defines the adventure seed (structure, **story hook vs. paperwork** so openings are not “papers please” alone, **First opening** appendix: no PC proper name in prose before the first user message).
- `skills/character.txt` contains system-level character rules and a user-level template section (marked in the file). The API renders the user section as the user message.

## Editing

- Use Mustache-compatible variables (e.g. `{{campaignConcept}}`, `{{#factions}}...{{/factions}}`, `{{languageInstruction}}`).
- If you rename a file, update every `LoadPrompt` / Mustache usage in `go/internal/gamesession/` and `go/internal/promptmgr/` and this doc.

## Prompt catalog (by path)

| Path | Purpose | Used by |
|------|---------|---------|
| `core/system.txt` | Core DM rules, JSON play envelope (no full combat mechanics — see `skills/combat.txt`) | `composeSystemMessages` (first system message) |
| `core/style.txt` | Global narrative style | `composeSystemMessages` |
| `rules/no_prefatory_guard.txt` | Forbids prefatory/meta-text | Campaign routes; consolidated stacks as loaded by code |
| `rules/json_output_guard.txt` | Strict JSON for campaign/stages | Campaign core, stages |
| `rules/json_output_guard_dm_play.txt` | DM `/generate`: envelope JSON; no bare `{}` | `/generate` |
| `rules/language_spanish.txt` / `rules/language_english.txt` | Language directives | Many routes |
| `rules/length_guard.txt` | Reply length / continuation | `composeSystemMessages` (late) |
| `rules/memory_summary.txt` | Session summary wrapper | When `sessionSummary` set |
| `rules/scene_grounding.txt` | Geography / beat discipline | Appended to consolidated `/generate` system text |
| `rules/vellaris_world.txt` | Authoritative-geography rules for an imported Vellaris world | `renderVellarisWorldInject` (`/generate`) |
| `rules/intent_router_system.txt` | Intent classification | `intentRouter.js` |
| `templates/campaign/generator.txt` | Campaign metadata builder + Mustache user slice (`---` separated) | `/generate-campaign`, `/generate-campaign-core` |
| `templates/campaign/stage_factions.txt` | `factions` array | `generateCampaignStage('factions')` |
| `templates/campaign/stage_majorNPCs.txt` | `majorNPCs` array | `generateCampaignStage('majorNPCs')` |
| `templates/campaign/stage_keyLocations.txt` | `keyLocations` array | `generateCampaignStage('keyLocations')` |
| `templates/campaign/world_context.txt` | DM-ONLY block describing the generated campaign world (regions, named places) | `renderCampaignWorldContext` in `campaign_world.go` |
| `templates/dm/inject_initial.txt` | Opening campaign injection | `/generate` initial |
| `templates/dm/inject_explore.txt` | Exploration injection | `/generate` exploration |

| `templates/dm/player_response_envelope.txt` | DM JSON envelope schema | `/generate` |
| `templates/dm/party_context.txt` | Multi-PC names / opening | Party block |

| `templates/dm/combat_entry_handoff.txt` | Combat entry handoff | `/generate` when entering combat |

| `skills/investigation.txt` | Investigation | Investigation mode |
| `skills/decision.txt` | Decision framing | Decision mode |
| `skills/character_generation_scope.txt` | Character route scope (not a play turn) | `/generate-character` |

| `templates/character/world_context.txt` | The table's regions and named places for a character sheet | `characterWorldSystemBlock` (`/generate-character`) |
| `skills/character.txt` | Character generation system + user section | `/generate-character` |

## Troubleshooting

- If a stage fails, `GameState.rawModelRequest` and `GameState.rawModelOutput` are populated for debugging.
- The server logs outgoing messages as `OUTGOING` / `DEBUG` entries — check terminal logs.
